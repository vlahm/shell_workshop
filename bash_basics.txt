Bash (Unix shell) basic commands
--------------------------------

These commands are available natively on Mac OS and Linux, or through Git Bash on Windows.

Read anything inside angle brackets (e.g. <foo>) as a variable, i.e. not literally.

Anything preceded by "-" indicates an optional argument, called a "flag".
Here's a command without a flag:

    mkdir dir1/subdir1

and with a flag:

    mkdir -p dir1/subdir1

Use this to decipher any shell command: https://explainshell.com/

--------------------------------


1. GET MANUAL PAGE FOR ANY SHELL COMMAND
(NOTE: manual pages not installed by default on Git Bash)

man <command>


2. PRINT WORKING (CURRENT) DIRECTORY

pwd


3. LIST FILES AND DIRECTORIES (FROM THE WORKING DIRECTORY UNLESS SPECIFIED)

ls
    -l (include metadata)
    -R (recursive)
    -a (include hidden files and directories, i.e. those prefixed with a ".")


4. CHANGE DIRECTORY

cd <directory>

special values:
    .. (parent directory)
    ~ (home)
    - (previous)
    / (root)


5. MAKE AND REMOVE DIRECTORY

mkdir <directory>
rmdir <directory> (only works if directory is empty; otherwise see rm)


6. CREATE EMPTY FILE

touch <file>


7. OPEN FILE IN TEXT EDITOR (file will be created if it doesn't exist)

nano <file> (simple text editor)
vim <file> (advanced text editor)


8. REMOVE FILES AND DIRECTORIES

rm <file>
    -r  (recursively - USE WITH CAUTION)
    -f  (force - USE WITH GREAT CAUTION)
    -rf (both - EXTREME CAUTION)


9. MOVE AND/OR RENAME FILES AND DIRECTORIES

mv <from> <to>
    -i ("interactive": ask to confirm if something will be overwritten)

mv foo* dir1   # move all files beginning with "foo" into dir1/
mv foo? dir1   # move all files with 4-character names beginning
               # with "foo" into dir1/
               # These wildcards are called "glob characters" and there
               # are many more. They're basically simplified Regex


10. COPY FILES AND DIRECTORIES

cp <from> <to>
    -i (interactive)
    -r (recursive)


11. PRINT CONTENTS OF FILES

cat <file>     #print full contents
head <file>    #print first n lines (10 default)
tail <file     #print last n lines (10 default)
fail -f <file> #watch as the file changes


12. CONTROL SEQUENCES

Tab:    autocomplete
↑:      retrieve previous command
Ctrl-c: stop the running command
Ctrl-u: delete to start of line
Ctrl-w: delete previous word
Ctrl-l: clear screen
Ctrl-a: jump to start of line
Ctrl-e: jump to end of line
Ctrl-r: search command history
        (start typing command, Ctrl-r again to cycle through matches,
         → when you find the command you want)
Ctrl-d: end input / log out / close terminal (pane) / EOF
Ctrl-z: suspend a program (fg to resume)


-----------------------------------------

MORE ADVANCED COMMANDS

some commands take more detailed arguments, using this form:

    command -parameter argument

for example, this command for finding files that are not directories,
a maximum of 5 levels below the working directory, and ending in ".txt"

    find . -maxdepth 5 -name '*.txt' -type f

-----------------------------------------


12. SEARCH FOR FILES/DIRECTORIES

find <search string>
    -maxdepth x (only search down x levels)
    -type (f for files, d for directories, etc.)
    -name (search by name; accepts glob characters)
    -iname (case insensitive name search)
    -atime (search by last-access time)

# run the head command for all found files:

	find . -name '*.txt' -type f -exec head {} \;


13. SEARCH FOR TEXT STRINGS WITHIN FILES

grep <search string> <file or directory>
    -r (recursive)
    -P (with regular expressions)
    -l (return filenames only)

14. MINIMAL PROGRAM FOR PAGING THROUGH TEXT FILES
use pgup, pgdn, u, d, j, k to scroll; /, n, n to search; q to quit

less <file>


15. RUN AS ROOT (DANGEROUS, BUT NECESSARY FOR SOME INSTALLATIONS AND ADMIN ACTIONS)

sudo <command>


16. INSTALL AND MANAGE PACKAGES FROM THE COMMAND LINE

brew   # macOS; must install homebrew first
pacman # Windows; must install MSYS2, which is an alternative to Git Bashapt    # Ubuntu/Debian-based Linux distros


16. PIPE THE OUTPUT OF ONE COMMAND INTO ANOTHER COMMAND WITH | operator

grep -r 'my search string' | less
